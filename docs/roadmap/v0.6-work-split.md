# v0.6 work split and contracts

The plan is `docs/roadmap/v0.6-knowledge-and-parallelism.md`. All work happens in the dev clone `~/Development/vajra` on branch `v0.6-knowledge`. The installed copy at `~/.claude/skills/vajra` is protected by the live guard, so never edit it.

Rules for every stream:
- Test with `HOME=$(mktemp -d)`.
- Never write the real `~/.claude/vajra` state.
- Don't commit.
- Don't run `install.sh` or `generate-manifest.sh` against the real HOME.
- Each stream adds `tests/**/run-*.sh` scripts, which `tests/run-all.sh` picks up automatically.

## In scope for v0.6
Roadmap items:
- 1: knowledge ledger
- 2: write gate
- 3: automatic read-back
- 4: write-back from deliveries
- 5: task graph
- 6: wave scheduler
- 7: structured worker reports
- 9: forgetting

Plus three fixes:
- **Router free-text capture:** `fleet`, `campaign`, `cost`, `ralph` and similar subcommands capture whatever text follows them.
- **Guard false positive:** a Bash command whose heredoc or quoted string merely mentions a protected path is blocked, even though it writes elsewhere. Example: `cat > ~/Development/x.md <<EOF ... ~/.claude/skills/vajra ... EOF`. The guard must judge only real write targets, not text inside heredocs or quoted arguments to non-mutating commands.
- **`git branch -d` / `git pull` inside the skill core:** keep these blocked. That is by design.

Deferred: 8 (declarative crews), 10 (spec artifacts), 11 (agent memory, which belongs in the mahabharat-agents repo), 12 (consolidation).

## Contracts

### `scripts/vajra_kb.py` (python3 stdlib only)

**Project id.** The first 16 hex characters of the sha256 of `git rev-parse --path-format=absolute --git-common-dir` (run from cwd). Outside git, use `global`.

**Storage.** `~/.claude/vajra/kb/<project-id>/`:
- `events.jsonl`: append-only, HMAC-chained with the Vajra key, same scheme as the practice log. This is the source of truth.
- `kb.sqlite`: FTS5 index derived from the events. Fall back to LIKE if FTS5 is unavailable.
- `INDEX.md`
- `pending/<id>.json`

**Record fields.**

| Field | Format |
|---|---|
| `id` | `kb-` + 6 hex |
| `type` | `decision`, `fact`, `lesson`, `delivery` or `pitfall` |
| `title` | ≤ 120 characters |
| `body` | ≤ 2000 characters |
| `scope` | `{paths: [globs], agent}` |
| `applies` | `always` or `on_topic` |
| `source` | `{kind: user\|verified\|proposed, session, commit, evidence}` |
| other | `valid_from`, `invalid_at`, `superseded_by`, `expires`, `tags` |

**Commands.** All support `--json`. Exit codes: 0 ok, 2 usage, 3 gate refused.
- `add --type --title --body --paths --applies --source user|verified|proposed --evidence <file> --session`
  - `proposed` writes to `pending/`.
  - `verified` requires an evidence file showing a green verify-work run.
- `search <q> [--k N] [--paths p1,p2] [--format ids|full]`. The `ids` format prints one line per hit: `kb-xxxxxx  type  title`.
- `show <id>`
- `prime --budget <tokens>`: prints the `always` lessons and the last 5 decisions as one-line pointers, inside `<untrusted-data source="vajra-kb">`.
- `supersede <old> <new>`, `retire <id>`, `restore <id>`
- `approve <id>` and `reject <id>`: require a TTY, like atman.
- `pending`, `rebuild`, `export`, `gc`, `doctor`
- `forget <id>`: user only; writes a tombstone.

**Write gate.** A write is refused (exit 3, audit-logged as a hash only) when it contains:
- secrets: AKIA/ASIA keys, `-----BEGIN`, `ghp_`/`gho_`, `sk-`, `xox[bp]-`, JWTs, high-entropy strings of 40+ characters
- injection patterns
- content over the size caps
- URLs with query strings

If an existing record has the same type and scope and a near-duplicate title (Jaccard ≥ 0.6), the write returns `deduped` with that record's id.

### `scripts/vajra_tasks.py`

**Storage.** `~/.claude/vajra/campaigns/<slug>/tasks.json`.

**Task fields.** `{id, title, owner_agent, deps[], files[globs], acceptance[], status, attempts, evidence, branch, worktree}`, where `status` is one of `pending`, `ready`, `claimed`, `in_progress`, `done`, `blocked`, `question`, `failed`.

**Commands.**
- `add`, `dep`
- `validate`: exits 2 on a dependency cycle, an unknown agent (not in `~/.claude/agents/*.md`) or an unknown dependency.
- `ready`
- `claim <id> <worker>`: atomic, using a mkdir lock.
- `report <id> <status> [--summary]`
- `close <id> --evidence <file>`
- `status <id>`
- `waves`: prints a JSON list of waves, in topological order. Tasks whose `files` globs overlap go in separate waves.
- `graph`: Mermaid output.

Only this script changes a task's status.

## Streams

### K: knowledge
Owns:
- `scripts/vajra_kb.py`, `tests/kb/*`, `docs/commands/kb.md`
- the kb parts of `atman/atman.py` and `scripts/atman.sh`: `atman.sh review` lists pending kb records, and `atman.sh approve kb-*` delegates to `vajra_kb.py approve`
- `SECURITY.md`: may only append a kb section

### H: hooks, router, read-back
Owns:
- `hooks/session-start.sh`: appends the output of `vajra_kb.py prime --budget 1500`.
- `scripts/vajra_route.py`:
  - appends the top 3 kb hits (`search --format ids`)
  - handles `/vajra remember <text>` by calling `vajra_kb.py add --source user --type fact`, and says so in its output
  - fixes free-text capture: `fleet`, `campaign`, `cost`, `ralph` and the rest only match when followed by their real arguments; otherwise the input is a deliver ask
- `hooks/pre-tool-use.sh`:
  - protects `~/.claude/vajra/kb/` and `campaigns/*/tasks.json` against direct writes; running the scripts stays allowed, and reading stays allowed except the key
  - fixes the heredoc/quoted-text false positive described above
- `SKILL.md`, `README.md`, `docs/architecture/ARCHITECTURE.md`, `docs/commands/help.md`
- tests for all of the above

### T: tasks and the deliver workflow
Owns:
- `scripts/vajra_tasks.py`, `tests/tasks/*`
- `workflows/vajra-deliver.js`, `workflows/vajra-feature-build.js`, `tests/workflows/*`
- `docs/commands/deliver.md`

Deliver changes, by phase:
- **Understand:** the first agent runs `vajra_kb.py search "<ask>" --format ids --k 5`, with the ask passed through the existing quoted-args mechanism. The hits go into the plan brief as data.
- **Plan:** returns tasks with `files` and `deps`. The workflow registers them with `vajra_tasks.py` (`add`, then `validate`).
- **Execute:** waves are computed in JS with the same algorithm as `vajra_tasks.py waves`, because the workflow script can't read files. Each wave runs as `parallel()`, capped by `args.maxInFlight` (default 4).
- **Workers:**
  - Each worker first runs `vajra_tasks.py status <id>` and returns the cached result if the task is already `done`.
  - A worker returns `{status: progress|done|blocked|question, summary, artifacts, evidence_cmds}`.
  - `done` is only a claim. The task closes on vidura's verdict, checked in code.
  - Never paste one worker's summary into another agent's prompt.
- **On done:** the final agent records knowledge with `vajra_kb.py add --source verified --evidence <verify-work json>`:
  - one `delivery` record
  - the plan's decisions
  - one `lesson` for each fix round that went from failing to passing

  Anything unverified is written as `--source proposed`.
