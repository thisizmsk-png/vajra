Source: the v0.6 integration review.

## Shared contracts (new)

- **Signed evidence.** `scripts/vajra-verify-work.sh` adds an `"hmac"` field to `evidence.json`. The value is HMAC-SHA256 with the Vajra key, computed over the canonical JSON of the object without `hmac` (`sort_keys`, separators `(',', ':')`, UTF-8).

  Evidence counts as **green** only when all of the following hold:
  - every command exited 0;
  - `treeStable` is true;
  - `git.head` equals the current HEAD of the repo it is checked in, or a named commit given by the caller;
  - the file sits under `<repo_root>/data/walkthroughs/*/evidence.json`;
  - the hmac verifies;
  - the commands are not all trivial (`true`, `:`, `echo …`, `exit 0`).

  `vajra_kb.py` and `vajra_tasks.py` both implement this same check.
- **User-tier token.** The router (in the UserPromptSubmit hook, which can read the key) calls `vajra_kb.py add --source user --user-token <hex>`. The token is HMAC-SHA256(key, `"user\0" + title + "\0" + body`). `vajra_kb.py` refuses `--source user` unless the token verifies. Agents can't read the key, so they can't mint it.
- **Session id.** The router's bare-ask line tells the model to pass `session_id` (the hook payload's `session_id`) in the `vajra-deliver` args. Deliver passes `--session <session_id>` to `kb add`. `vajra_kb.py` refuses proposed and verified writes without a session id that matches `^[A-Za-z0-9-]{8,}$`.
- **applies=always.** Only user-tier records, or records a human approves, may be `always`. `verified` and `proposed` records are forced to `on_topic`; an approval may promote them.

## Fixer G: guard
Owns `hooks/pre-tool-use.sh`, `tests/hooks/*` and the guard rows of `docs/architecture/ARCHITECTURE.md`.

1. **CRITICAL.** The PRE_AWK `.hmac-key` masking (around :285, `masking()` around :277) also masks redirect targets, so `echo "<hex>" > "$HOME/.claude/vajra/.hmac-key"` is allowed. The same goes for `printf`, `>>`, single quotes, `.HMAC-KEY` and `.hmac-key.tmp`. Never mask a redirect target, or any word after `>`, `>>`, `<` or `|`. Test every one of these variants.
2. Match any abbreviation of `--source` for `vajra_kb.py add`: `--s`, `--so`, `--sou`… with `=` or a space. The token contract above is the real fix, so keep this check as an extra layer.
3. False positives on Vajra's own generated commands:
   - Treat quoted arguments as data when the segment is `python3|bash <…>/{vajra_kb.py,vajra_tasks.py,vajra-campaign.sh}`.
   - Add `vajra-campaign.sh` to `DATA_SCRIPTS`.
   - `msgarg`: `prevw ~ /^-[A-Za-z]*m$/ || prevw == "--message"`, so `git commit -qm` and `-am` are covered.
4. Performance:
   - Use the awk path from 1024 chars.
   - Skip glob expansion for tokens with no `/` or `~` when `fastcwd=1`.
   - Above about 2000 tokens, block with a clear message.
   - Lower the raw cap to 512 KB.
   - Test cases: a 4,093-char `python3 -c "(a),[b] …"`, a 31 KB version of the same, a 4 KB python heredoc, `node -e` at 4 KB, and a 512 KB cat heredoc. Every case must finish in under 3 s. Report the measured times.
5. Protect `campaigns/*/.tasks.lock` from Write, Edit and mkdir.
6. ARCHITECTURE.md: replace the "well inside its 10 s timeout" claim with the measured bounds.
