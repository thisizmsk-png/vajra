# Vajra v0.5 — "make it real"

*Plan written 2026-10-11 from four audits (routing/engine, hooks/scripts, Atman self-learning, state-of-the-art research).*

## Product view

**Who it's for:** a solo developer or small team running Claude Code who wants it to finish real, multi-step work with less babysitting, without giving up safety.

**The job:** turn "do X" into verified, finished work. That means routing to the right specialist, keeping state across sessions, running parallel crews, proving work is done, and getting measurably better over time.

**Where v0.4 stands:** Vajra describes those capabilities well, but almost all of it is prose the model is asked to act out:
- **Hooks:** none are registered by the installer.
- **Blocking:** the guard exits 1, which Claude Code treats as a warning, not a block.
- **Signing:** a fresh install writes an empty HMAC key, and the shipped signature makes every other user's install look tampered.
- **Campaigns:** "SQLite + HMAC" persistence is never called.
- **Routing:** "0-token" routing is done by the model reading config.
- **Fleet:** the coordinator crashes on macOS bash 3.2 and deletes agent work on exit.
- **Atman:** the learning loop records every outcome as "success", so it has never learned anything.

On a fresh install, the user experience is almost the same as plain Claude Code, but they pay about 6.5k extra tokens per routed task.

**The bet for v0.5:** fewer features, each one enforced by code, using native Claude Code primitives wherever they now exist. Every claim in the README must be backed by a test.

## Research view: what to build on

| Vajra area | Native primitive (2026) | Decision |
|---|---|---|
| Fleet crews | Dynamic workflows (`~/.claude/workflows/*.js`: deterministic, journaled resume, schema-validated outputs, worktree agents) | Rebuild crews as saved workflows; retire `fleet-coordinator.sh`. |
| Proof-of-work | `Stop`/`SubagentStop` hooks with exit 2 | Keep `verify-work`; require ≥1 check; evidence tied to the git tree. |
| Routing tiers 1/3 | UserPromptSubmit hook (runs outside the model) and native skill descriptions | Make tier 1 a real 0-token hook that injects a suggestion. Drop the model-read config and the tier 3/4 prose. |
| Guard hook | PreToolUse exit 2, deny JSON, `onFailure: "block"` | Fix the exit codes, canonicalize paths, match only command/path fields. |
| Memory tiers / dream | Native auto memory (`MEMORY.md` index + topics) | Defer to native memory. Keep the untrusted-data wrapping rule. |
| Plan mode | Native plan mode + ExitPlanMode | Thin wrapper: native plan mode plus Vajra's plan template. |
| Campaigns | Long-running-harness pattern (JSON feature list where only `passes` flips, progress file, startup smoke test) | A real `vajra-campaign.sh` that signs state with openssl, so the key never enters context. |
| Atman | Eval-gated changes (SkillsBench: self-written skills give ~0 average gain unless gated); ACE-style delta updates | Real outcome signal (PostToolUseFailure, verify-work results), proposals only, never auto-writes the core, eval cases in `claude plugin eval` format. |
| Cost | `/usage`, statusline | Keep `vajra-cost.sh`; dedupe by message id; current pricing. |
| Integrity | Local signing | Sign at install time with the user's own key; don't ship a `.sig`. |

## Scope

1. **Hooks and security:** exit-2 contract and fail-closed traps; canonical, case-insensitive path checks; no scanning of file contents; protect the learning state and `~/.claude/agents`; real stdin payload fields; tests rewritten against the real contract.
2. **Registration and install:** the installer merges a `hooks` block into `~/.claude/settings.json` (backed up, idempotent), creates a real HMAC key, signs the manifest locally, and installs the workflows. Add `vajra doctor` to check the wiring.
3. **Routing:** a 0-token UserPromptSubmit router with case-insensitive, specificity-ordered patterns; cortex delegation at every tier; fixed agent mapping (duryodhana is non-security, backtests go to karna, drona added).
4. **Crews as workflows:** `feature-build`, `security-audit`, `incident-response`, `architecture-review`, and a `sabha` debate. Each has typed outputs, a fix loop, a bounded number of rounds, and a vote counted in code, and is tested offline with a stub harness.
5. **Campaigns:** `vajra-campaign.sh` (create/list/show/pass/checkpoint/resume) holding features.json and progress.md, HMAC-signed by the script.
6. **Loop and verification:** Ralph with a permission mode, max-turns, stall detection and logs; verify-work requires at least one command and diffs against HEAD plus untracked files.
7. **Atman v2:** real signals, proposals under `~/.claude/vajra/proposals/`, a human approve/reject command, no writes to config, sanitized names and hashed traces, and seed eval cases.
8. **SKILL.md:** valid frontmatter, about 80 lines, each subcommand pointing to its own doc (progressive disclosure).
9. **Honest docs and CI:** README, SECURITY and ARCHITECTURE claims match the code; a GitHub Actions CI runs the suite.

**Not now:** plugin packaging (the repo layout change is big), GEPA-style automatic prompt search, and agent teams.
