# Launch Assets: README, demo, and channel copy

## The demo (the single load-bearing asset, build this FIRST)
Devs decide whether to engage in ~15 seconds; a page with no visible demo loses most of them. The demo is the reason curators feature you, newsletters republish you, and creators react.
- **Format/spec:** terminal recording, 20 to 40s, **self-evident on mute in <10s** (a "before vs after" / "naive way fails → your tool saves it" split-screen is ideal). 16pt+ font, ~1200×720, **<5MB** for GitHub README autoplay. Tools: `vhs` (charmbracelet, scriptable), `gifski`, `terminalizer`, `asciinema` (embeddable), Kap.
- **Pick the most "10x screenshottable" moment**, the one beat that makes a viewer go "wait, it does *that*?" Ship rough-but-clear; iteration beats polish.

## README-as-landing-page (converts traffic from EVERY channel)
Conversion structure, top to bottom:
1. **Hero:** problem-led one-liner (NOT the category label) → one-sentence define-the-term → the demo GIF **above the fold**.
2. **Install in 30 seconds**, copy-paste, ≤2 core lines, optional steps separated. Quick-start in the first ~200 words.
3. **The problem** (2 to 4 lines of relatable pain) → **what you get** (concrete bullets) → **first 10 minutes** (task-oriented examples).
4. Tasteful real badges (license, platform, a genuine differentiator badge), a `good first issue` link (contributor funnel), a low-key star CTA, and a **star-history chart** (~+15% conversion).
5. Keep the category keyword (for GitHub search/topics) in the **footer**, not the hero. Set repo **topics** (real discovery surface).

## X / Twitter launch thread
- **No link in tweet 1** (suppresses reach). Link goes in the last 1 to 2 tweets. **Demo GIF in tweet ~3** (the money-shot beat).
- Structure: pain hook (1) → define the rising term + the ladder (2) → one concrete capability per tweet with the command/proof (3 to 8) → the boring-essential stuff (9) → install + repo (10) → a *genuine question* to invite replies (11).
- Post Tue to Thu morning PT. **Reply to every reply in the first 2 hours**, comment velocity is the algorithm.

## X Article / Dev.to / Hashnode (long-form, SEO)
Publish on your own blog first, cross-post with `rel=canonical`. Title around the rising term for search demand. Expand each thread beat into a section. Keep any "fleet/multi-agent" content short; it's the demo, not the thesis.

## LinkedIn post
- LinkedIn suppresses external links → **link in the first comment**, say "link in comments."
- Hook in the first 2 lines (all that shows before "…see more"); generous line breaks; reply to early comments fast. Founder-lesson register ("I stopped trusting X. Then I made it prove itself."), not an announcement. Native video/document-carousel outperform link posts.

## Reddit post (text/self post)
Lead with the relatable pain → 3 to 5 concrete bullets of what it does → the demo → **honest limitations** (builds trust on Reddit) → a genuine question → repo link LAST. Title is pain-led, first-person, discussion-shaped ("I got tired of X, so I built Y, feedback welcome"), never the category label. See `channels.md` for sub rules.

## Title formula (decoded from high-performers)
First-person "I built…", lead with the concrete capability/outcome, put social proof in the title if you have it ("2,000 downloads in 10 days"), use humble/interactive suffixes ("looking for feedback", "roast my…"). Winners say what it *does*, never the category.
